Calls I made

1. Followed the protocol's top-level hello.hc, not the brief's host.hc spelling.
   No duplicate field or other wire extension was added. This discrepancy was
   raised during the work; no answer was needed to implement the written contract.
2. hello.herdr_auto is null when hc is installed but its generation cannot be
   observed without starting it. start-team does the actual resolution. Reporting
   herdr in that case would misrepresent a later successful hc auto start.
3. Migration 3 also stores private per-terminal PID/foreground PID/tab identities.
   These are needed for safe ownership checks and crash/retry-safe tab reuse; they
   add no wire fields. Historical migrations 1 and 2 were not changed.
4. Status fallback shares a label-filtered list across members within a runner
   pass (200 ms cache); normal status reads use the subscription. Missing recent
   creation events get an authoritative list before being declared gone.
5. Kept/replaced programs are considered gone and left alone. Cleanup of the
   team's other recorded terminals continues without killing replacement shells.
6. terminal.run has environment overrides but no unset operation. An empty
   OPENCODE_CONFIG_CONTENT prevents inherited config content from superseding the
   launch file; HOME/PATH and launch variables are passed directly. There is no
   clean-shell bootstrap on hc. Codex's shared existing --no-daemon is removed
   before re-adding exactly one flag when that binary advertises support.
7. The hc end-to-end stand-in is a deterministic Python stdin/OSC program rather
   than a shell-only pi stub: hc omitted foreground metadata for the shell stub,
   which correctly failed adoption's PID/cwd checks. No model requests or real
   conversations are needed for the fixture scenario.
8. Changed only the old 150 script's session allocation to fresh lugarn-test-* so
   running that requested regression meets this brief's isolation rule.

uses a no-inference stand-in; native pi/OpenCode observations were separate.

hc observations beyond the supplied facts

- For the shell fixture, foreground metadata was absent even with a root status;
  a Python foreground program supplied the PID/cwd required by adoption.
- terminal.list requires a JSON object for labels; null was rejected. Empty
  filters now encode as {}.
- heartbeat is a standalone method with params.seq. missed is a standalone
  method with params.seq and params.terminals, not an ordinary terminal event.
- The first test stub incorrectly emitted JSON in OSC 7501. The correct field
  format was verified with the upstream example and real core output:
  https://herdr.dev/core/#status-from-the-source
  Event shapes also match the upstream API description:
  https://github.com/herdrdev/herdr-core/blob/master/schema/README.md#events
- pi/OpenCode startup observations are given above. No other supplied hc fact
  was contradicted by these runs.

Isolation and cleanup

No command mutated terminal or lifecycle state on a default hc core or the
Herdr 0.9 default server. No default run/send/keys/kill/rm/label/keep/stop/restart
operation was issued. No herdr-app document was read or written. No global
harness configuration or credential file was intentionally read or edited;
the native harness probes used temporary configuration homes.

There was an isolation gap in the first two development broker test passes:
the newly added hello probe could make a read-only connection to the existing
default hc socket. I did not trace those individual subprocesses, so I cannot
claim zero default-core reads. The probe would connect only if the socket existed;
it performs only hello. I fixed the tests by injecting HCProbe and giving CLI
fixtures an absent hc binary. All live mutation tests used fresh private sessions,
refused the known default core id, and stopped/removed their own core in cleanup.
The 0.9 script's unscoped session-list calls were read-only; its before/after
session snapshots are identical.

All listed private session state directories and hc sockets were checked absent
at the end. No existing session was reused or removed.
